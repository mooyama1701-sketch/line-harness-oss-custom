# 2. プロジェクトの背景

現在、OSSとして公開されている「LINE Harness」を利用し、大山独自の機能・画面・運用方法を追加した改造版を開発する。

改造版は、大山自身が利用するだけではなく、第三者にも提供できる形にする。

第三者は、複雑なCloudflareの設定やソースコードの手動操作を行わず、次のようなコマンドを実行するだけで、自分自身のCloudflareアカウント上にLINE Harness環境を新規構築できる状態を目指す。

```bash
npx @airestart/create-line-harness
```

実行後は対話形式で必要情報を入力し、以下のCloudflareリソースを自動的に構築する。

```text
・Cloudflare Worker
・Cloudflare D1
・Cloudflare R2
・Cloudflare Pages
・Worker Secrets
・データベース初期設定
・初期管理者情報
・LINE公式アカウント情報
```

# 3. プロジェクトの目的

本プロジェクトの目的は、以下の3点である。

## 3.1 LINE Harnessの独自改造版を開発する

元のLINE Harnessを基盤として、以下のような独自変更を行える状態にする。

```text
・管理画面のデザイン変更
・独自機能の追加
・不要機能の削除
・初心者にも分かりやすい画面への改善
・大山の提供サービスに合わせた初期設定
・独自の運用ルールへの対応
```

## 3.2 第三者向けの専用インストーラーを開発する

第三者が専用コマンドを実行し、対話形式でCloudflare環境を新規構築できるようにする。

```text
第三者のPC
    ↓
専用npxインストーラーを実行
    ↓
第三者自身のCloudflareへログイン
    ↓
必要情報を対話形式で入力
    ↓
Worker・D1・R2・Pagesを構築
    ↓
管理画面URL・Webhook URLを表示
```

## 3.3 継続的に保守・更新できる仕組みを整える

元のLINE Harnessに新しいバージョンが公開された場合でも、必要な変更を大山版へ取り込める構成にする。

また、大山版についても独自のバージョン管理を行う。

# 6. 開発方針

## 6.1 最初は一つのリポジトリで管理する

初期段階では、元のLINE Harnessと同様に、一つのリポジトリ内で本体とインストーラーを管理する。

```text
line-harness-custom
├── apps
│   ├── worker
│   └── web
├── packages
│   ├── create-line-harness
│   ├── db
│   └── その他パッケージ
├── migrations
├── docs
├── LICENSE
└── README.md
```

理由は以下のとおり。

```text
・元のLINE Harnessの構造を大きく変えずに済む
・本体とインストーラーの動作確認がしやすい
・元OSSの更新を取り込みやすい
・開発初期の管理が簡単
```

将来的に必要になった場合は、インストーラーだけを別リポジトリへ分離する。

---

## 6.2 既存本番環境とは完全に分離する

現在稼働している本番環境は、本プロジェクトの開発・検証には使用しない。

### 現在の本番環境

```text
Worker：
line-harness-production

D1：
line-harness

Pages：
line-harness-production-admin
```

### 開発・検証環境例

```text
Worker：
line-harness-custom-dev

D1：
line-harness-custom-dev

R2：
line-harness-custom-dev-images

Pages：
line-harness-custom-dev-admin
```

テストには、本番のLINE公式アカウントではなく、テスト用LINE公式アカウントを使用する。

---

## 6.3 第三者の秘密情報は外部へ送信しない

以下の情報は、利用者のPCから利用者自身のCloudflareへ直接登録する。

```text
・Cloudflare認証情報
・LINEチャネルアクセストークン
・LINEチャネルシークレット
・LINE LoginチャネルID
・LIFF ID
・管理画面用APIキー
```

大山が管理するサーバーやAPIへ、秘密情報を送信しない設計とする。

ログにも秘密情報をそのまま表示しない。

# 7. 仮名称

以下は現時点での仮名称とする。

| 用途          | 仮名称                                  |
| ----------- | ------------------------------------ |
| GitHubリポジトリ | `line-harness-custom`                |
| npmスコープ     | `@airestart`                         |
| npmパッケージ    | `@airestart/create-line-harness`     |
| 実行コマンド      | `npx @airestart/create-line-harness` |
| ローカル保存先     | `~/.line-harness-custom`             |
| 設定ファイル      | `.line-harness-custom-config.json`   |
| 初期プロジェクト名   | `line-harness-custom`                |

公開前に、サービス名・商標・利用者への分かりやすさを考慮して正式名称を決定する。

なお、第三者向け正式版の名称としては、`create-line-harness-dev`よりも、以下のような名称が望ましい。

```text
@airestart/create-line-harness
@airestart/create-line-crm
@airestart/create-line-system
```

`dev`は「開発途中」「検証版」という印象を与えるため、正式配布版には使用しない方針とする。

# 12. 主なリスクと対策

| リスク             | 内容                 | 対策                      |
| --------------- | ------------------ | ----------------------- |
| 本番D1の誤更新        | 既存D1へマイグレーションを実行する | 本番と別Cloudflare名・別環境で検証  |
| Workerの上書き      | 同名Workerをデプロイする    | 重複チェックと上書き禁止            |
| Pagesの上書き       | 既存管理画面を更新する        | 新規プロジェクト名を使用            |
| LINE Webhookの切替 | 本番LINEが検証Workerへ向く | テスト用LINE公式アカウントを使用      |
| 秘密情報の漏えい        | トークンがログやGitへ入る     | マスク処理、Git除外、公開前確認       |
| 公式版への戻り         | updateで公式コードが適用される | 初期版ではupdate機能を無効化       |
| 元OSSとの競合        | 上流更新と独自変更が衝突する     | upstream-syncブランチで検証    |
| npm誤公開          | 不要ファイルや秘密情報を公開する   | npm pack --dry-runで事前確認 |
| ライセンス違反         | 著作権・MIT表示が不足する     | LICENSEとクレジットを維持        |
| 初心者が構築できない      | 説明やエラーが難しい         | ベータテストとマニュアル改善          |

# 17. プロジェクトの基本原則

本プロジェクトでは、以下の原則を守る。

```text
・本番環境を使って実験しない
・秘密情報をCodexへ必要以上に渡さない
・変更前に必ず現状を調査する
・一度に大きな変更を行わない
・工程ごとにGitコミットを分ける
・各工程で動作確認を行う
・公式版の変更をそのまま本番へ適用しない
・第三者のCloudflare環境を無断で変更しない
・初期版は新規構築に限定する
・安全性を機能数より優先する
```

# 18. 最終目標

本プロジェクトの最終目標は、第三者が以下のコマンドを実行し、専門的なCloudflare構築作業を行わずに、大山版LINE Harnessを利用開始できる状態を実現することである。

```bash
npx @airestart/create-line-harness
```

```text
コマンド実行
    ↓
必要情報を対話形式で入力
    ↓
利用者自身のCloudflareへ新規構築
    ↓
管理画面URLを取得
    ↓
LINE DevelopersのWebhookを設定
    ↓
LINE Harnessの利用開始
```
